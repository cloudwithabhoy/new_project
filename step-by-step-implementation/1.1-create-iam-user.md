# 00 — Create the IAM user (`eks-user`)

## Goal
Create an IAM user that (1) can run **eksctl** to create/manage the EKS cluster, and (2) can push
images to **ECR** (used by the Jenkins pipeline). Generate an access key for CLI + Jenkins.

## Why
Everything downstream authenticates as this user — `aws configure` on the EC2 instance, `eksctl`, and
the Jenkins ECR push. **eksctl needs broad permissions** because it provisions a lot under the hood:
a VPC + subnets + security groups (EC2), IAM roles (cluster, nodes, OIDC/IRSA), all orchestrated via
**CloudFormation** stacks. So the user needs EC2 + IAM + CloudFormation + EKS permissions.

ARN of the user we created: `arn:aws:iam::169424082295:user/eks-user`

## Prerequisites
- AWS account with admin access to create IAM users.

## Steps

### 1. Create the user (IAM console)
- IAM → **Users → Create user** → name **`eks-user`**.
- **Console access:** not needed — we use it via CLI/keys. Leave disabled.

### 2. Attach permissions policies
Add permissions → **Attach policies directly** → attach these:

| Policy | Type | Why it's needed |
|---|---|---|
| `AmazonEKSClusterPolicy` | AWS managed | core EKS cluster permissions |
| `AmazonEKSWorkerNodePolicy` | AWS managed | worker-node permissions |
| `AmazonEKSServicePolicy` | AWS managed | EKS service (legacy; eksctl historically references it) |
| `AmazonEC2FullAccess` | AWS managed | eksctl creates VPC / subnets / SGs / ENIs / instances |
| `AWSCloudFormationFullAccess` | AWS managed | eksctl provisions **everything** via CloudFormation |
| `IAMFullAccess` | AWS managed | eksctl creates IAM roles (cluster, nodes, OIDC, IRSA) |
| `AmazonEFSCSIDriverPolicy` | AWS managed | *(optional)* EFS CSI driver — only if you use EFS volumes |
| `AmazonEC2ContainerRegistryPowerUser` | AWS managed | **ECR push/pull** — required for the Jenkins pipeline |
| `eks-req` | **Customer managed** | grants `eks:*` — the actual EKS **API** access to create/describe/delete clusters & node groups (see below) |

> **`AmazonEC2FullAccess` does NOT include ECR.** Despite ECR's old name ("EC2 Container Registry"),
> `ecr:*` is a separate service — that's why `AmazonEC2ContainerRegistryPowerUser` is a **separate,
> required** attachment for image push. (We hit "Could not find credentials matching ecr:..." until
> this was added — see `02`.)

**The `eks-req` custom policy** (IAM → Policies → Create policy → JSON):
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "VisualEditor0",
            "Effect": "Allow",
            "Action": "eks:*",
            "Resource": "*"
        }
    ]
}
```
**Why this exists:** the AWS-managed `AmazonEKSClusterPolicy` / `AmazonEKSWorkerNodePolicy` are designed
to be attached to the **cluster's / nodes' IAM roles** — they let the *cluster* talk to AWS. They do
**not** grant a *user* the right to call the EKS API. So to let `eks-user` (and eksctl) actually run
`CreateCluster`, `DescribeCluster`, `CreateNodegroup`, etc., you need `eks:*` — which is what this
custom policy adds. Without it, eksctl fails with EKS API "not authorized" errors.

### 3. Create an access key
- User → **Security credentials → Create access key** → "Command Line Interface (CLI)".
- Save the **Access Key ID** + **Secret** — used in two places:
  - `aws configure` on the EC2 instance (step `03`), and
  - the Jenkins **`aws-ecr`** credential (step `02`).

## Notes (security — read this)
- This user is **very privileged** (`IAMFullAccess` + `AmazonEC2FullAccess` + `AWSCloudFormationFullAccess`).
  That's fine for an **eksctl admin**, but putting these *same* keys in Jenkins means a Jenkins
  compromise = near-admin over the whole account.
- **Better split (harden later):**
  - **Jenkins (CI):** a *separate* user with **only** `AmazonEC2ContainerRegistryPowerUser` (ECR push).
  - **eksctl admin:** `eks-user` (broad), used from your laptop/CLI — **not** stored in Jenkins.
- For true least-privilege, eksctl publishes a **"Minimum IAM policies"** set (narrower than the
  FullAccess policies) — worth adopting once you're comfortable.

## Verify
After `aws configure` (step `03`):
```bash
aws sts get-caller-identity
# Account: 169424082295 ... Arn: arn:aws:iam::169424082295:user/eks-user
```
